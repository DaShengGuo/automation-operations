# 登录卡顿整改报告 — 2026-08-16

目标流程(用户口径):QQ 与游戏全关闭 → 打开 QQ → 搜群名 → 进聊天窗口 →
取号 → 打开游戏 → 登录 → 任务 → 退出登录。**进聊天窗口、取号、打开游戏
三个操作之间不允许插入任何其他操作。**

---

## 一、卡顿根因 1: QQ 群聊天框三条杠乱点(已修复, 已验证 3 次)

- **现象**: 用户反馈「一直在点群聊天框右上角三条杠」。
- **根因**: 进群流程的「已在聊天页」判定曾依赖「聊天设置」desc,
  群聊页被误判为未进入 → 反复点右上角三条杠菜单再找入口。
- **修复**(core/qq_provider.py):
  - `enter_group` 零点击快路径: 已在聊天页直接返回;
  - `_is_in_chat` 明确**排除**「聊天设置」desc;
  - 全流程无任何三条杠点击路径(代码复核确认)。
- **验证**: QQ 冷启动取号链实测 3 次, 12s 完成
  (打开 QQ → 进群 → 读 7 条消息 → 配对 2 组账号 → 返回游戏),
  进群→取号→回游戏之间**零额外操作**。

## 二、卡顿根因 2: 無法登入弹窗(两轮修复)

- **run 10 现象**: 游戏记住上次失败会话, 冷启动直接弹「無法登入」弹窗;
  弹窗描述文本含「中央站」, 检测器误判为 LOGIN_PROVIDER 登录方式页 →
  点击描述文字而非按钮 → 60s PTC 超时 → WAIT_HOME 卡 131s → 336s 被杀。
- **修复第一轮**:
  - 新增 `LOGIN_FAILED_DIALOG` 状态, 检测顺序置于 LOGIN_PROVIDER **之前**;
  - 弹窗处理: 点「以其他帳號登入」清残留会话,
    **绝不点「再試一次」**(会用残留旧凭据重试, 不可控);
  - `login()` 入口 step 0: 先检测并处理该弹窗。
- **修复第二轮(run 11 实测)**: 规则 `[無法登入]` 误匹配登录方式页
  底部「無法登入嗎?」链接 → 干净页面被误判为弹窗 → 登录重试死循环。
  改用**弹窗独有词「再試一次」**判定 + 回归测试断言干净方式页不误判。
- **验证**: run 11/12 无一次误判; 回归测试锁定行为。

## 三、卡顿根因 3: MIUI 密码保存弹窗压住浏览器(run 12, 已修复)

- **现象**: PTC 表单提交后, MIUI 弹出「是否将账号密码存储在智能密码
  管理中」(取消/存储), 弹窗压在浏览器上;**认证返回等待只查游戏前台,
  从不处理该弹窗** → AUTH_RETURN_TIMEOUT 120s 超时 ×2。
- **run 12 实测时间线**:
  - 09:19:15 提交 → 09:21:15 超时(整 120s, 弹窗全程未处理);
  - 09:21:36 弹窗处理器点「取消」——但第一次认证已死;
  - 09:22:27 重试再次提交 → 弹窗重现 → 09:24:27 再次超时;
  - 09:23 截图实锤: 弹窗仍挂在已填好的表单上;
  - 深层影响: 弹窗压住期间认证上下文失效, 游戏最终回来时
    弹「無法進行認證」(prep13 截图)。
- **修复**(automation/pokemon_go/web_context.py): `wait_game_return`
  循环内检测并关闭该弹窗 — **只点「取消」, 绝不点「存储」**
  (账号密码不入系统密码库, 业务密码仅存本地 runtime.db;
  OCR 定位失败时 u2 text 兜底)。
- **run 13 实测生效**: 每次提交后的弹窗均在等待循环内被关闭
  (09:35:57 / 09:38:43), 认证链路不再停滞 — 认证请求即时送达 PTC。
- **追加修复(认证早失败)**: run 13 观察到错误已显示在屏幕
  (浏览器红字「用户名或密码错误」), 等待仍烧满 120s 整窗;
  现 `wait_game_return` 每 5s 轮询 `classify_error`, 检测到
  无效凭据/网络错误立即失败返回 — 坏账号不再 3×120s 空转。
- 与既有安全原则一致(adapter 弹窗处理器同款「不保存」注释)。

## 四、状态机崩溃(与卡顿同场发现, 已修复)

- **run 12 两次崩溃**: 「非法状态迁移: HANDLE_POPUPS → DETECT_PAGE」
  (09:21:43 / 09:24:54), 靠看门狗恢复兜住。
- **根因**: device_worker 弹窗处理后按页面状态路由
  (HOME→EXECUTE_TASK / LOGIN→LOGIN / 其他→DETECT_PAGE),
  但 TRANSITIONS 迁移表里 HANDLE_POPUPS 只允许 EXECUTE_TASK —
  代码逻辑与迁移表不一致。
- **修复**: 迁移表补充 DETECT_PAGE / LOGIN 两条合法路由 +
  回归测试 `test_popup_routes_after_handling`。
  状态机+游戏适配器测试 **71 个全部通过**。
